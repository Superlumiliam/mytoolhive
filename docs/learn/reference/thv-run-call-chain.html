thv run 调用链速查

诊断口诀：先找“最后成功点”，再判断它位于输入构建、状态交接还是长期执行。父进程成功只证明 detached 子进程已 spawn，不证明 server ready。

runCmdFunc → runSingleServer → BuildRunnerConfig → NewRunConfigBuilder → policy + pull → EagerCheckCreateServer → SaveState → RunWorkloadDetached → spawnDetached → thv start NAME --foreground → restartCmdFunc → RestartWorkloads → loadRunnerFromState → RunWorkload → Runner.Run → secrets/middleware → runtime.Setup (deploy/start container) → transport.Create/Start (start Proxy/bridge) → readiness → client config → Running → monitor/retry

阶段证据

输入构建
命令行错误；无 RunConfig；看 run.go、run_flags.go、builder/retriever tests。
状态交接
RunConfig、Starting/Error、status JSON 中的 process_id；看 detached spawner tests。
长期执行
Proxy 日志、container 日志、status；看 Runner.Run、runtime/transport tests 与 manager retry tests。

失败语义

最后成功点下一份证据不要误判
RunConfig 未生成CLI 校验、registry/image、policy/pull 错误不要先查 container；它还没有进入执行阶段
RunConfig 已保存、无 PIDspawn error、status transition、Proxy 日志文件创建不要把状态文件存在等同于 workload 已运行
PID 已写、status ErrorProxy 日志中的 runtime/transport/middleware 错误不要把 shell 返回 0 等同于 ready
Running 后退出IsRunning、ErrContainerExitedRestartNeeded、退避重试不要只看最初的启动日志
readiness warning探测响应与 client config当前 warning 后仍可能继续运行

事实源：CLI run path、Workload Manager、Runner。
