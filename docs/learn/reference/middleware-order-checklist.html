Middleware 顺序评审速查

reverse-wrap 后 index 0 是请求最外层：[A,B,C] → A(B(C(handler)))。

评审问题
输入成本body/Origin 是否在任何解析、认证和外呼之前受限？
身份谁建立可信 identity？后续谁读取？credential 在何时 swap/strip？
语义谁先解析 MCP method/tool？mutate 是否先于 validate？
决策authz 的输入是否完整？拒绝是否进入 audit/telemetry？
出口header/token/signature 变换是否贴近 backend？后面还有谁会修改请求？
旁路health、metrics、well-known、prefix handlers 是否刻意绕过链？
双路径CLI pre-populated 与 Populate/operator 两条装配路径是否都有测试？

证据：assembly · Runner · proxy wrapping。
