第 10 课：Operator 治理是两级控制环

校准日期：2026-07-17 · 预计 25 分钟 · 唯一目标：给定一个 MCPServer 故障，你能判断它发生在 Operator 收敛 proxy-runner 资源，还是 proxy-runner 经 Kubernetes runtime 收敛 backend，并用 owner、RBAC、generation 与 condition 找到责任边界。

任务钩子

MCPServer 已有 Ready condition，但 backend StatefulSet 不存在；或者 Deployment 正常，proxy-runner 日志却报 Forbidden。只看 CR status 不够，因为 Operator 与 proxy-runner 分别拥有一段控制链。

MCPServer CR (desired state) │ ├─ Operator: validate refs/spec + status ├─ ServiceAccount / Role / RoleBinding ├─ RunConfig ConfigMap + checksum ├─ proxy-runner Deployment └─ client-facing Service │ mount runconfig.json + downward generation ▼ proxy-runner Pod / Runner │ Kubernetes Deployer + scoped RBAC ├─ backend StatefulSet └─ backend Services (HTTP)
两级所有权：Operator 不在 MCP 请求数据路径上，也不直接执行 Runner；proxy-runner 才读取 RunConfig、装配治理 proxy，并凭 namespace Role 操作 backend StatefulSet/Service。proxy-runner 与 backend 默认使用不同 ServiceAccount，前者的控制权限不等于后端容器的业务权限。

它不是一次安装事务：首次创建 Deployment 或 Service 后，Reconcile 会返回并 requeue；后续事件再驱动下一轮幂等收敛。Operator controller 只直接 watch 自己的 proxy Deployment/Service，不直接 watch proxy-runner 创建的 backend StatefulSet。

Condition 不是端到端探针：Operator 的 Ready/Phase 主要根据它所列出的 MCPServer Deployment pods 分类；backend 由 pod 内 proxy-runner 进一步创建。必须把 CR condition 与 proxy-runner 日志、backend StatefulSet/Pod/Service 一起对账。

Generation 为什么有两条通道

ConfigMap volume 会 live-update。滚动更新期间，旧/新 proxy-runner pod 若都读到最新 generation，可能同时改 backend。Operator 把 generation 同时冻结在 pod annotation/downward env；proxy-runner 用 env 覆盖文件值，Kubernetes deployer 再用 generation gate 避免旧 pod 覆盖新期望。

spec.replicas 控制 proxy Deployment，spec.backendReplicas 控制 backend StatefulSet；前者为 nil 时保留 HPA/KEDA/人工伸缩，stdio proxy 副本会被限制为 1。HTTP transport 才创建 backend headless/ClusterIP Services。多 proxy 副本缺少 Redis session storage 主要产生 advisory condition，不必然阻断资源创建。

先预测，再展开

修改 ConfigMap 后，旧 pod 应立即采用新 generation 吗？

不应。downward env 冻结 pod 创建时的 generation，优先于 live-mounted file；新 generation 应由滚动出来的新 pod负责。

Role 只需要读 ConfigMap 吗？

不是。MCPServer proxy-runner 要 create/update/delete StatefulSet/Service，并读 pods/log/attach 等；remote proxy 因不创建 container，有更小的独立规则集。

Owner reference 能替代 finalizer 吗？

不能简单等同。owner refs 支持垃圾回收已拥有对象；finalizer 让 controller 在 CR 真正消失前执行显式清理。检查每个二级 backend 资源究竟由谁拥有/删除。

A. RunConfig ConfigMap 未创建。

B. proxy-runner 日志报创建 StatefulSet Forbidden。

C. backend Pod 为 ImagePullBackOff。
