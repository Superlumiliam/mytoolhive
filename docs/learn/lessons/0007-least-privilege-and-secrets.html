第 7 课：最小权限是多道边界的交集

校准日期：2026-07-17 · 预计 25 分钟 · 唯一目标：给定一个 workload，你能从 permission profile、volume、network isolation、Docker gateway 和 secret reference 追到 runtime 的有效权限，并指出意图、解析值和实际强制点分别在哪里。

任务钩子

配置使用了名为 none 的 profile，但又挂载了宿主目录、通过明文 env 注入 token，并允许 Docker gateway。它“看起来安全”吗？不能只看一个字段：文件、网络、秘密和 runtime 实现共同决定最终能力。

文件系统

profile 的 read/write mount 是意图；CLI --volume 还会扩展它。当前 Docker 路径负责落地，Kubernetes runtime 尚未执行这份 profile。

网络

profile 描述目标，isolateNetwork 才启用 Docker isolation/egress；Docker gateway 是额外、端口无关的显式例外。

秘密

RunConfig 尽量携带引用，Runner 在部署前解析成 env/auth/header 的内存值；Kubernetes 则主要通过 native SecretKeyRef 交付。

先求“有效权限”，再谈默认值

profile object > explicit profile name/path > registry image metadata profile > builtin network default │ ├─ apply network mode override └─ merge explicit volumes into read/write mounts │ ▼ RunConfig effective profile + isolation flags + secret refs │ Runner.WithSecrets (actual values, memory) │ ▼ runtime.Setup → DeployWorkload(profile, env, options, isolateNetwork)
审计原则：builder 产出的是“有效意图”，runtime 才是强制点。permission profile 与 isolateNetwork 不是同义词；secret reference 与 secret value 也不是同一个数据层。

默认不等于最小：没有显式或 registry profile 时使用 builtin network profile，它允许全部出站网络，不是 deny-all 模板。需要最小 egress 时必须给出更具体的 profile，并确认 isolation/runtime 真正执行它。

Kubernetes 当前存在执行缺口：pkg/container/kubernetes/client.go 目前忽略 permission profile 与 network isolation 参数；Operator 虽构建 profile/volumes，后端 StatefulSet 并未因此获得等价强制。只有明确进入 pod template 的配置才可视为已落地。

先预测，再展开

--volume ./data:/data 会自动是只读吗？

不会。只有 :ro 才进入 profile 的 read mounts；默认进入 write mounts。重复 target 会保留先出现的 mount 并记录 warning。

isolateNetwork=true 加 allowDockerGateway=true 仍是完全隔离吗？

不是。Docker gateway flag 是显式例外，且不受 permission profile 端口规则约束；它只对 Docker + isolation 有意义。Kubernetes runtime 当前连 profile/isolation 本身都尚未等价执行。

secret 解析失败会在容器启动后才发现吗？

Runner 在 middleware 和 runtime.Setup 前调用 WithSecrets；正常路径应在 deploy 前失败。但 JSON import、Operator env 注入等入口具有不同的预验证/交付机制，需沿具体路径判断。

ValidateSecrets 只检查 name,target=ENV 格式吗？

不是。普通 secret 会通过 environment parser 调用 user provider 读取实际值以验证可用性；它虽不写入 EnvVars，但意味着“验证”已经跨过 secret store 的读取边界。

A. profile 中的只读 mount。

B. secret provider 返回的 token。

C. 已创建容器的实际 network/mount。
